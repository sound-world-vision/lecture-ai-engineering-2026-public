主な傾向：

- `max_seq_len=1536〜2560` かつ `with_system_prompt=True`（④⑤⑥⑧）：`after/both_rate` = 89.7〜93.1% と最高で、format・content とも大幅向上。
- `max_seq_len=512` かつ `with_system_prompt=False`（②③）：`after/both_rate` = 50.0/51.7% で学習前より改善するが、長い設定には届かない。
- `max_seq_len=512` かつ `with_system_prompt=True`（①）：`after/both_rate` = 0.0% で学習前（1.7%）より悪化。用語リスト付きシステムプロンプト＋データ拡張の長い入力を 512 で切ったため崩壊した。
- `train/loss` は `with_system_prompt=True`（0.0085〜0.0102）の方が `False`（0.0711〜0.0713）より低い。学習時間は 420〜1150 秒で、`max_seq_len` や system prompt の有無で変動。
- データ拡張の有無：`with_system_prompt=False` では拡張ありの方が `after/both_rate` が 15〜17 ポイント高い（1024: ⑪ 41.4% → ⑫ 56.9%、1536: ⑩ 34.5% → ⑬ 51.7%）。一方 `system_prompt=True`（1536、④⑤ vs ⑨）では拡張あり 89.7〜93.1% に対し拡張なし 91.4% と差が小さく、効果は限定的。

結論：

- 特にシステムプロンプトを追加したときなど、質疑が長い場合はそれを考慮して `max_seq_len` を設定しないと学習が崩壊する
- 今回のテストデータに対しては `max_seq_len` は 1536 以上に設定しても結果の改善には寄与しない
- 用語一覧をシステムプロンプトに追加した学習データに加えた場合、劇的に性能が改善する(50% => 90%程度)
- 上記システムプロンプトを学習データに加えない場合、データ拡張が性能改善に寄与(15~17%程度)

### ファインチューニングが向く場面・向かない場面についての考察

#### ファインチューニングが向く場面

- 演習でも宿題でも形式への追従については学習しやすい傾向がみられているため、特定の形式で回答が欲しい場合には向いていると考えられる
  - しかし、一般の LLM でも structured_output をサポートしているケースが多く、本当に有用かはそれらを使用できないか、精度が不十分な場合に限られる可能性がある
- 内容についても回答の文面が教師データに近づいていくので、特定の文体で回答したい、などというケースで有用な可能性がある
- クラウドの LLM は性質が変化していく可能性があるので、その影響を排除したい場合

#### ファインチューニングが向かない場面

- structured_output や RAG などで十分な品質の回答が得られる場合は、ファインチューニングを行う必要性が乏しい
- 開発チームに LLM の学習に関する知見が十分ない場合
  - 今回の実験でも一部のパラメータの設定の不備に気づかず学習が崩壊したケースがあったため、これに気づけないと運用に問題が生じる
